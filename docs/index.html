Methodology

Same prompt, strict output, review before scoring

Every model gets the same match order and scoring constraints. The app filters completed matches and unresolved placeholders out of weekly prompts, then parses the final TSV-style answer into a review table before anything is saved.

01 Prompt input

Upcoming resolved matches only. No TBD, seed placeholders, or already-completed rows.

02 Required output

One TSV code block, league headers allowed, one prediction per match in the given order.

03 Review gate

Parser flags illegal scores, wrong winners, duplicate rows, ambiguous teams, and count mismatches.

04 Scoring

Correct winner = 1 point. Exact score = +1 point. Maximum = 2 per completed match.

Use web search to look up the latest information about each team's recent form, roster changes, standings, and head-to-head records for the 2026 season. Think step by step about each matchup before predicting. Then predict the winner and score for all matches below.

After your analysis, respond with a final answer section containing exactly one TSV codeblock total.

Inside that one codeblock, write the league/tournament header line exactly as shown below, then one prediction per line in ONLY the format:
"TeamName score"

Then write the next league/tournament header and its predictions. Match the order given in each block. Do not add explanations, extra labels inside the codeblock, or commentary after the final answer section.

Example block:
LCS - LCS 2026 Spring Playoffs
All matches in this block are Best of 5. Possible scores are 3-0 or 3-1 or 3-2.
1. C9 vs FLY
2. LYON vs TL

Data provenance

One source of truth

Scores and match data come from the maintainer's local SQLite database only. The public repository can improve the app and documentation, but external commits do not change benchmark results because they cannot be validated against the private workflow history.
